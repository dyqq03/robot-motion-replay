# 运行时边界与故障定位

本文件描述使用回放系统时要核实的能力，不宣称内置快照已经包含所有服务器新增功能。本次生成/离线验证不启动控制栈、不访问串口、不执行真机动作。

|场景|应核实的运行行为|包内检查不能证明的部分|
|---|---|---|
|不含手指流|手节点缺失不应阻止纯手臂/颈部包；按参与链判断依赖|该机前后端是否仍有全局手部就绪限制|
|含手指流|播放前核对参与手在线、实测新鲜、串口唯一占用；不满足应明确提示并拒绝起播|不能仅根据存在目标话题认定电机已连接|
|起播|从新鲜实测平滑到第一帧；历史要求约1s，实际差距/限速优先|包首帧正确不能消除失能/控制权交接导致的下坠|
|结束|核对保持/恢复目标和约1s交接；颈部目标应为逻辑0°|不能只改包末帧，忽略播放器随后发出的恢复目标|
|起栈|手臂到认可初始姿态后，再启动/使能双手到认可手型|磁盘配置与运行进程缓存可能不同|
|抓取/释放事件|先确认实际服务器的事件格式、服务、时钟、正反播放/重复触发策略和失败处理|内置旧播放器桩测试不证明当前事件协议兼容|

抓取事件是服务调用，不等于某一帧手指角度。没有事件的旧包须保持兼容；不把服务动作结果伪造成反馈。遇到带事件包时读实际播放器/录制器实现并扩展离线消息桩，尚未支持则明确标为未验证，不能删掉事件后声称完整回放通过。

本技能普通动作入口生成角度流。它没有新增远端节点管理或抓取事件导出功能。`offline_backend.py` 验证绑定哈希的本地播放器加载及正反角度消息，不能证明真实电机使能、控制频率、串口、运行服务或动力学表现。

## 更新依赖和运行证据

```bash
python scripts/state_audit.py --out work/verification/state_before.json
# 导入用户提供的资源或采用新参考后：
python scripts/state_audit.py --compare work/verification/state_before.json --out work/verification/state_after.json
```

输出当前默认机器、标定、参考、映射、模型、碰撞规则及播放器哈希差异。它是本地差异工具，不自动激活profile或同步文件。

已有来自实际检查的运行资料可用 `--runtime-evidence 文件.json` 导入，至少包含 `host`、`observed_at_utc`、`source`，其余可保存实际加载路径/哈希、驱动方向、节点状态、反馈年龄、起栈/结束目标等。工具拒绝不同默认目标的证据，并始终标为“导入证据，未实时验证”。旧时间记录不能代替本次在线反馈。
