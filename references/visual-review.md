# 视觉审阅与修改反馈

## 先判断什么

新动作先写短 `intent`：含义、两三个关键姿态、掌面/指尖方向、参与侧、头手配合和节奏。优先检查关键姿态是否有辨识度，再完善全段。额角致敬、胸前比双指、向前指示是不同语义；含义明确时不增加确认步骤。

按本次动作选择审阅项目：

|项目|具体看什么|修改方向|
|---|---|---|
|语义|不看文件名能否识别；是否有多余动作|重塑关键姿态或删掉无意义段落|
|腕肘|手腕是否折得突兀、肘部是否过高/过外|测量几何关系，优先调整肩肘，不用J7硬凑目标|
|掌面与手型|掌面方向、弯指辨识度、拇指和四指关系|调整朝向；需要间隙时先稍张再弯|
|节奏|是否每个中间点都停、忽快忽慢、机械循环|用经过点与必要停留，调整运动段而非盲目缩总时长|
|协同|抬臂与手型形成是否重叠；视线先后是否合理|按语义重排相位；非参与侧保持安静|
|收势|是否绕回旧参考、有额外抬落或首尾跳变|从当前参考重建；另外核对运行时交接|

J7接近零、肘部较低等是某些动作的偏好，不是所有动作固定要求。关节0°与掌部/小臂的几何共线不同；参见设计文档的姿态测量。

## 实际查看与记录

```bash
python scripts/motion.py render work/drafts/包名
python scripts/visual_review.py prepare work/drafts/包名 --times 0 0.8 1.5 2 2.4 3 4 5
```

时间必须在实际导出时钟内；省略时默认均匀12帧。`review_sheet.jpg` 保留视频的正面、侧面及双手近景，`review_evidence.json` 记录实际解码时间与媒体/设计哈希。均匀采样不能代替检查关键衔接；疑似卡顿处加密采样并检查速度曲线。观看完整可播放视频时关注真实节奏。若工具只能查看静帧，明确记录采样范围和局限，不声称逐帧完整观看。

**示例结构，不是可直接套用的评价：**

```json
{
  "method": "实际查看正侧面关键帧和衔接采样；按实际情况说明是否观看视频",
  "viewed_files": ["review_sheet.jpg", "keyframes.jpg"],
  "observations": [
    {"time_s": 2.4, "aspect": "腕肘", "observation": "写此时实际看到的姿态和缺陷", "verdict": "needs_changes"}
  ]
}
```

```bash
python scripts/motion.py review work/drafts/包名 --reviewer assistant --status needs_changes --assessment work/assessment.json --notes '本轮问题和修改方向'
```

缺省状态为 `pending`。只有已实际查看、所有已记录缺陷解决后才显式写 `--status passed`，观察项 verdict 全部改成有事实依据的 `acceptable`。没有结构化观察、未解决缺陷或过期媒体均不能通过。`prepare` 会使旧视觉审阅失效；重新渲染/修改设计后重新准备并查看。

每轮记录追加到包内 `review_history.json`，保留问题、时刻与当时输入哈希；`visual_review.json` 表示本轮状态。旧输入上的通过记录不能使新输入通过。

脚本只验证结构、时间和文件一致性，无法确认操作者是否真的观看，也无法自动判断美观。不要用备注长度、图像哈希或视频可解码来充当审美证明。

## 修改前后对照

```bash
python scripts/visual_review.py compare work/drafts/旧草稿 work/drafts/新草稿 --out work/comparisons/对照.jpg --fractions 0.2 0.4 0.6 0.8
```

对照按归一化时钟取样，并标注两版实际时间，不保证语义阶段自动对齐。阶段时序变化较大时分别选择相应时间查看；视角布局应一致。旧图、新图和具体改动共同支持判断，不用“已优化”代替观察。

失败试验保留在草稿目录；碰撞失败返回修改姿态/路径，视觉失败返回语义/几何/节奏设计。数值和视觉两条分别通过，候选单姿态通过不替代完整路径。
